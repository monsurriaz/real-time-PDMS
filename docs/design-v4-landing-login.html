What's inside

Built like an operations tool, not a form.

Everything below is running in the product today — no waitlists, no "coming soon" tiles.

Real-time tracking that admits when it's stale

Positions arrive over a socket every few seconds. If the connection drops, the interface says "reconnecting" instead of leaving a dot sitting on a road it left ten minutes ago.

Proof at the door

A photo, a one-time code, or a signature — recorded against the delivery, not taken on trust.

Photo OTP Signature

Cash on delivery, reconciled

Every taka a rider is holding, per rider, settled with an audit trail rather than an edited total.

৳84,320
held by riders right now

Riders are vetted, then matched by distance

Applications are reviewed before anyone carries a parcel. After that, assignment is a geospatial query against who's actually on shift and nearby — with workload as the tie-breaker.

Numbers you can defend

Zone performance, delayed-parcel alerts and revenue are counted at read time from deliveries and payments. Nothing on the dashboard is a stored total that drifted.

Build notes. The hero map is a real MapLibre instance using the existing dark-styled tiles, not an image — the rider pins are the same marker components the app uses, so they can't drift. A radial veil sits over it for text contrast; that's the one gradient in the system and it exists to make text legible over imagery, not for decoration. Everything else keeps the frozen rules: no gradient fills on surfaces or buttons, no drop shadows, separation from 1px borders. The bento cells, tier table, and FAQ are new layout patterns but reuse existing tokens, badges, and the LifecycleRail. The login's left panel now carries the same map treatment plus a live product card, which is what fills the dead space in the current build.
